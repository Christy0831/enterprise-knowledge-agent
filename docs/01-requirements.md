# 01 · 需求与成功标准

## 题号、用户与目标

选择原题 **题目3：企业知识问答 Agent**。目标用户是需要查找制度或产品说明的员工；目标是获得可追溯的回答，知道依据来自哪里、是否存在冲突，以及还缺什么资料。

原始考核要求保留在 [test.md](../test.md)。以核心链路为范围：CLI 输入、文档检索、原文读取、模型依据工具反馈选择下一步、结构化回答及实际运行记录。

## 输入与材料

- 问题：非空字符串；可附带结构化用户/助手对话历史。
- 知识资料：合成 JSON 文档，含唯一文档 ID、标题、ISO 版本日期、片段 ID 和原文。可选适用范围和优先级未知时使用 `null`。
- 文档检索及片段读取工具：本地实际执行；可注入临时或持续不可用故障。
- 真实模型：DeepSeek 官网 API。无可用模型时可使用明确标注的离线 Mock，但它不证明模型决策效果。

## 输出约定

每次任务产生 JSON，包含 `answer`、`citations`、`gaps`、`conflicts`、`status`、`completed`。引用包含文档 ID、片段 ID、版本日期及连续原文。Trace 记录实际调用参数、观察结果、下一步和一句简要依据，不记录内部思维过程。

## 验收矩阵

| 必须验收项 | 成功标准 | 对应用例 |
| --- | --- | --- |
| 明确答案 | 单制度快照回答30天，引用D01且原文一致 | 01 |
| 文档冲突 | 读取D01和D02，补查适用范围等；无法裁决则列出30/15天与双方引用并追问，不因日期新就选15天 | 02 |
| 资料外问题 | 不凭模型常识回答公司资料外事实，说明资料缺口 | 03 |
| 改写后的相似问题 | “垫的钱…报账”能被真实模型改写后找到报销制度，结论与标准问法一致 | 04 |
| 上下文追问 | 结合报销历史理解“那需要哪些材料”，引用D03重新读取的原文 | 05 |
| 工具失败 | 将真实错误反馈模型；恢复后可继续，持续失败时明确未完成，不能虚报成功 | 06、07 |

附加验证：无历史的代词问题追问（08）；替换文档为45天后答案和引用变化（09）；达到执行上限返回 `step_limit`（10）；产品事实引用（11）。

## 动态决策要求

真实模式至少出现“模型选择动作 → 本地执行工具 → 工具结果回传 → 模型调整下一步或结束”的循环。执行器仅调度和校验，不按命中数量硬编码模型的业务动作。

需要保存至少两条真实模型执行路径，体现不同观察引发不同动作，例如：

1. 有直接证据：检索 → 读取 → 回答。
2. 发现冲突：检索 → 读取双方 → 补查 → 追问。
3. 首次无结果：原始查询 → 模型改写 → 读取 → 回答。

离线运行记录见 `examples/mock/`，真实模型路径见 `examples/deepseek/`。观察后的决策路径分析见 [manual-review.md](../examples/manual-review.md)。

## 执行边界

默认最多12步，可配置1～50；**每次工具调用（包含finish）计一步**，同一次模型响应返回多次工具调用也分别计数。超过上限时停止并返回未完成，保留中间Trace。单次API请求默认45秒超时。

项目使用合成资料，提供CLI与本地React界面，支持可选历史输入；暂未实现真实企业数据导入、权限服务、持久会话或线上部署。资料未给出的适用范围与优先级保持未知，冲突无法裁决时请求确认。

检索扩展见 [07](07-hybrid-retrieval.md)，React与流式交互见 [09](09-react-ui-and-streaming.md)。
