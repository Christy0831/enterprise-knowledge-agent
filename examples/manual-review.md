# 真实模型答案与决策路径复核

复核对象：`examples/deepseek/`最新完整运行（DeepSeek官网API、deepseek-flash、non-thinking、temperature=0）。本文件记录开发过程由Codex进行的源文与Trace人工核对，不声称提交者已亲自逐项审阅。

## 证据与结论

| 用例 | 核对结果 |
| --- | --- |
| 01明确答案 | D01原文30天，回答30天；D03材料补充也有独立结构化原文引用；没有把范围未知解释为新版本优先 |
| 02冲突 | 30天与15天均引用对应原文；读取双方后另起模型轮次补查；未因D02较新而选择15天，保留缺口并追问 |
| 03资料外 | 两个不同查询均0命中后返回资料不足，没有给火星氦含量数值 |
| 04相似问法 | 模型将“垫的钱/报账”检索为报销主题；答案30天，与标准问法一致，未再因同义表达强制补部门 |
| 05上下文 | 将“那需要准备哪些材料”理解为报销材料；本轮读取D03，三项材料均在原文中，没有只引用历史回答 |
| 06临时失败 | 首次search_docs确实返回UNAVAILABLE；下一轮模型再次检索，再读取后回答，未把失败当作0命中 |
| 07持续失败 | 原文读取持续失败，返回tool_error且无结构化引用；提及预览时明确标注未核实，未把预览当正式结论 |
| 08无历史追问 | 问题对象不明时请求补充，没有捏造指代对象或制度 |
| 09替换文档 | D01变更为45天及2026-05-01版本，输出45天且引用新版本；没有仍答30天，没有“专门制度自动优先”的效力推断 |
| 10执行上限 | 只允许一步，工具调用后返回step_limit，completed=false，没有继续读取或输出完整答案 |
| 11产品事实 | 依据D04回答支持添加和编辑字幕，没有给出来源未提供的效率或准确率数值 |

所有结构化引文的文档/片段/日期/逐字原文和本轮读取记录也由自动评估校验通过。自然语言语义支持仍需人工检查，不能仅凭逐字校验作保证。

## 至少两条真实观察后决策路径

### 路径A：单制度直接作答

文件：[01_clear_answer.json](deepseek/01_clear_answer.json)。

1. 模型第1轮选择search_docs，工具返回D01期限制度和D03材料清单。
2. 第2轮模型选择读取这两份资料；两个读取在同一响应中提出，不把它们描述为相互观察后的决策。
3. 模型收到原文后，第3轮提交answered，核心结论30天，引用与原文对应。

### 路径B：冲突查证后追问

文件：[02_conflict.json](deepseek/02_conflict.json)。

1. 第1轮search_docs返回D01、D02等候选。
2. 第2轮读取D01和D02，工具观察分别是30天/15天，范围与优先级未知。
3. **观察到双方原文后**，第3轮模型再次选择search_docs，查证范围、优先级和替代关系。
4. 补查没有独立裁决说明，第4轮模型提交needs_clarification，列出双方引用与待确认项。

路径A和B说明模型面对不同证据选择了不同后续动作和状态，执行器没有替模型挑选一个期限。

### 路径C：工具失败后调整

文件：[06_transient_failure.json](deepseek/06_transient_failure.json)。第1轮检索返回真实注入错误，第2轮模型选择再次检索；获得结果后读取原文并完成。对照 [07](deepseek/07_persistent_failure.json)，持续读取失败后模型最终选择停止并返回tool_error。

## 保留的限制

- 此处覆盖固定的小规模合成资料，不代表任何企业实际制度，也不证明大规模检索或长期稳定性。
- 第二轮真实验证发生过一次模型协议错误，复跑成功未查明其根因，详见开发记录。
- 部分模型回答字符串含字面量 `\\n`，原始记录有意保留；这影响排版，不改变事实、引用或任务状态。
- 以上是开发侧复核，提交者应独立运行并理解关键代码；个人学习和修改经历只能据实补充。
